# AI Testcase Lab

一个以手写代码为主的 AI 测试用例平台学习项目。

目标：每天约 2 小时，用 4 周逐步实现核心流程，并能够解释请求处理、数据库读写和模型调用的过程。该时间为学习目标，按实际进展调整。

## 核心范围

需求输入 → 功能点提取与确认 → 用例生成 → 人工编辑、采纳 → 入库与 Excel 导出。

- 项目管理：创建和查看项目。
- 需求输入：粘贴并保存需求文本。
- 功能点：模型提取、手动修改、确认。
- 用例生成：标题、前置条件、步骤、预期结果。
- 用例管理：查看、编辑、采纳、删除。
- 导出：Excel 文件。

## 四周目标

| 周次 | 目标 |
| --- | --- |
| 第 1 周 | 学习 FastAPI 与 SQLite，实现项目和需求的基础读写 |
| 第 2 周 | 接入模型，实现功能点提取、校验和确认 |
| 第 3 周 | 完成用例生成、管理和 Excel 导出 |
| 第 4 周 | 自己编写关键接口测试，修复问题，整理演示和说明 |

## 学习方式

- 从 FastAPI 和 SQLite 的基础开始，代码由学习者逐步手写。
- 每次围绕一个小功能，先明确输入和预期输出，再实现和验证。
- 结合具体请求，理解参数如何进入函数、数据如何保存、响应如何返回。
- AI 助手负责解释、拆解任务和协助排错；需要代写实现时再明确提出。
- 测试代码也由学习者逐步编写，保留自己的实践记录。

## 当前状态

已建立 FastAPI 应用入口、`GET /health` 接口和应用生命周期中的数据库初始化、关闭流程。

SQLite 初始化结构包含 6 张核心业务表，SQL 与 Python 初始化代码分开。原项目的 14 张表另存为完整结构参考，表关系与调整说明见 [数据库说明](docs/database.md)。

路由按模块组织，总路由统一接入应用。现有 `GET /product` 是空列表示例，调用 Service，尚未查询数据库。

```text
main.py                       # 应用创建、生命周期、接入总路由
database.py                   # 数据库连接、初始化和关闭
router/
├── router.py                 # 汇总各模块的 APIRouter
├── health.py                 # 健康检查接口
└── product.py                # 商品示例接口，调用 Service
services/
└── product_service.py        # 商品示例的处理逻辑
schemas/                      # 随业务接口添加请求、响应模型
sql/
├── schema.sql                # 核心业务表结构
└── reference/
    └── original-schema.sql   # 原项目完整表结构参考
```

`GET /health` 由 `router/health.py` 直接返回状态。`GET /product` 的调用链是：

```text
main.app → 总路由 → product 路由 → product_service.list_products()
```

项目管理使用 `projects` 命名；当前的 `product` 是已有学习示例，两者属于不同模块。
